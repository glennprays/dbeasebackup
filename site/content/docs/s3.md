title: S3 and compatible
description: Configure AWS S3, MinIO, Cloudflare R2 or another S3-compatible service, with the IAM permissions it needs.
---

`STORAGE_TYPE=s3` uploads to any service that speaks the S3 API, through the MinIO Go client. All targets share one bucket.

## Configure

```bash title=".env (AWS S3)"
STORAGE_TYPE=s3
S3_ENDPOINT=https://s3.eu-central-1.amazonaws.com
S3_BUCKET=my-db-backups
S3_REGION=eu-central-1
S3_ACCESS_KEY_ID=AKIA...
S3_SECRET_ACCESS_KEY=...
S3_PREFIX=backups/postgres
```

```bash title=".env (MinIO or other S3-compatible)"
STORAGE_TYPE=s3
S3_ENDPOINT=https://minio.internal:9000
S3_BUCKET=db-backups
S3_REGION=us-east-1
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
```

The bucket must already exist. `/health` checks that it does.

### Endpoint and TLS

`S3_ENDPOINT` sets the host and also decides TLS:

| `S3_ENDPOINT` | Connects to | TLS |
| --- | --- | --- |
| `https://minio.internal:9000` | `minio.internal:9000` | on |
| `http://minio:9000` | `minio:9000` | off |
| `minio:9000` | `minio:9000` | off |

> [!WARNING]
> `S3_ENDPOINT` is required, including for AWS. Use `https://s3.amazonaws.com` or the regional endpoint, for example `https://s3.eu-central-1.amazonaws.com`. When it is empty, the client rejects the endpoint and startup fails with `Endpoint:  does not follow ip address or domain name standards`. An endpoint without `https://` sends credentials and data in plain text.

Examples for common providers:

| Provider | `S3_ENDPOINT` | `S3_REGION` |
| --- | --- | --- |
| AWS S3 | `https://s3.<region>.amazonaws.com` | the bucket's region |
| Cloudflare R2 | `https://<account-id>.r2.cloudflarestorage.com` | `auto` |
| DigitalOcean Spaces | `https://<region>.digitaloceanspaces.com` | the Spaces region, e.g. `nyc3` |
| Backblaze B2 | `https://s3.<region>.backblazeb2.com` | the B2 region |
| MinIO | `https://<host>:<port>` | `us-east-1` unless configured |

## Object keys

Every object is stored at `<S3_PREFIX>/<filename>`, for example:

```text
backups/postgres/app-db_dump_20261122T020000Z.dump
backups/postgres/prod-cluster_basebackup_20261123T040000Z.tar.gz
```

Write `S3_PREFIX` without leading or trailing slashes. A trailing slash breaks the [retention](/docs/retention/) listing.

> [!CAUTION]
> Leave `storage.folder_id` and `storage.prefix` empty on S3 targets. `storage.prefix` is not applied yet. `storage.folder_id` is added to the key on upload, but verification and cleanup look under `S3_PREFIX` only, so they would never find those files and old backups would pile up.

## IAM permissions

The access key needs these actions on the bucket and nothing else:

```json title="policy.json"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::my-db-backups"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::my-db-backups/backups/postgres/*"
    }
  ]
}
```

`GetObject` is used by [verification](/docs/verification/) and `DeleteObject` by retention. Drop `DeleteObject` only if you set `retention_days: 0` everywhere and expire objects with lifecycle rules instead.

## Recommended bucket settings

- Block all public access.
- Turn on default encryption (SSE-S3 or SSE-KMS).
- Turn on versioning, or object lock in governance mode, so a leaked key cannot destroy history. Add a lifecycle rule that expires non-current versions.
- Uploads stream from the local file; large files are split into multipart uploads by the client automatically.
